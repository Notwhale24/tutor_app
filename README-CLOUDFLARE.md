# Cloudflare: сайт и подключение к Supabase

В проекте подготовлен Worker, который обслуживает сайт и передаёт запросы
`/supabase/auth/v1/*`, `/supabase/rest/v1/*`, `/supabase/storage/v1/*` в существующий
проект Supabase. База и файлы остаются в Supabase. Авторизация пользователя,
publishable key и политики RLS сохраняются. Прокси не использует service_role.

Это может помочь при недоступности домена Supabase у провайдера. Если недоступен
сам `workers.dev`, потребуется другой доступный адрес или хостинг. До публикации
и проверки без VPN решение сетевой проблемы не подтверждено.

## Проверить перед публикацией

- В Cloudflare открыть Workers & Pages → tutor-manager-app → Settings → Build.
  Уточнить подключённый репозиторий, ветку и команды сборки/публикации.
- Сверить имя существующего Worker с `wrangler.jsonc`. Этот файл предназначен
  для уже используемого Worker `tutor-manager-app` в аккаунте `notwhalerus`.
- В окружении сборки должны быть `VITE_SUPABASE_URL`,
  `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_APP_LOGIN_EMAIL`. Значения ключей и
  адрес входа не нужно публиковать в репозитории или пересылать в чат.
- Сначала проверить разницу между доступностью сайта и сервера Supabase без VPN.

## Сборка для Cloudflare

```powershell
npm.cmd run build:cloudflare
```

Этот режим использует корневой путь `/` и `.env.cloudflare`, где указан
`VITE_SUPABASE_PROXY_URL=/supabase`. Не задавать пустую или старую переменную
`VITE_SUPABASE_PROXY_URL` в окружении сборки: окружение имеет приоритет над файлом.
Публиковать нужно вместе Worker `cloudflare/worker.js` и статические файлы `dist`,
используя `wrangler.jsonc`; загрузка только папки `dist` не устанавливает прокси.
Для подключённой сборки команда публикации Wrangler: `npx wrangler deploy`.

## GitHub Pages

Обычная команда `npm.cmd run build` сохраняет путь `/tutor_app/`.
После установки и проверки Worker можно задать для сборки GitHub Pages:

```env
VITE_SUPABASE_PROXY_URL=https://tutor-manager-app.notwhalerus.workers.dev/supabase
```

Пока эта переменная не задана, сборка GitHub Pages обращается к Supabase напрямую.
Для применения через GitHub Actions нужно также передать переменную в `env`
шага Build в `.github/workflows/deploy.yml`. В конфигурации Worker уже разрешён
источник `https://notwhale24.github.io`.

## Проверка после публикации

1. Открыть `/supabase/auth/v1/health` у Worker. Ответ 401 без ключа означает,
   что запрос достиг Supabase; HTML приложения означает, что прокси не установлен.
2. Без VPN войти в приложение, проверить загрузку данных и вложений.
3. Изменить статус оплаты за прошлую неделю, дождаться сохранения и обновить
   страницу. Убедиться, что статус сохранился; повторить с VPN.

Нельзя считать одну успешную сборку подтверждением работы облачной базы или
доступности сайта у конкретного интернет-провайдера.
